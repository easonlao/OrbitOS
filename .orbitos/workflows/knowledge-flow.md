# Knowledge Flow Workflow

Knowledge Flow 是 OrbitOS 基础层的知识流转闭环。它把收件箱分流、知识沉淀、知识调用和结果反馈连接起来；它不是可选模块，也不复制另一套可见目录。

## 默认分流

按以下优先级判断，不因每个低风险输入都询问用户：

1. 用户明确指定目录或对象时，按用户指定处理。
2. 直接服务于正在推进的目标，进入对应项目的项目材料。
3. 仍需保留原貌、尚未消化的外部材料，保留为收件箱原件或来源集合。
4. 已经形成跨场景可复用的结论，提出 `knowledge_candidate`，进入知识草稿流程。
5. 只是未想清楚的想法、摘录或待办，保留在收件箱，不包装成知识。
6. 只有归属会实质改变，或涉及不可逆动作时，才标记 `unclear` 并询问一个最关键的问题。

文件命名、主题聚类、重复检查、来源链接和 MAP 同步属于 Agent 可执行的低风险整理，不应成为用户逐项决策。

## 批量确认

1. Triage 按来源或主题形成确认批次，展示每批的去向、影响和需要用户决定的事项。
2. 用户确认一个批次后，Agent 可以完成该批次内已声明的 ingest 和结构性整理，不逐文件重复确认。
3. 用户明确说“整理为知识草稿”时，该表达本身就是创建草稿的授权；不得再次询问同一授权。
4. 移动、删除、归档用户内容，或把草稿提升为 active knowledge，仍必须保留确认门。
5. 批次中存在冲突、命名冲突或不同意图时，只暂停对应条目，不阻塞整个批次。

## 知识调用

当用户询问“该怎么做、要不要做、如何判断、比较方案、分析风险收益”时：

1. 从 active knowledge 检索最相关的 1—3 张卡片；需要时再读取当前项目经验。
2. 对每张卡片检查过去场景、当前场景、成立条件和不适用边界。
3. 没有直接适用的卡片时，明确说明本次建议主要来自当前事实和一般判断。
4. 回答区分“已有知识”“当前事实”“本次推断”，知识支持的判断使用行内 Obsidian 引用。
5. 涉及行动或投入时，尽量给出第一步、测试周期、投入上限、止损条件和继续放大的条件。
6. Hindsight 只作为候选背景，关键结论仍回查本地主源；它不替代 active knowledge。

## 结果反馈回写

用户报告使用结果、验证结果或"这条经验不适用"时，记录一次 `knowledge_use` 事实，并选择反馈去向：

- 仅影响本次任务：留在 event，不制造知识。
- Agent 执行方式或踩坑：进入对应 Agent 的 Experience Capture。
- 只对当前项目成立：进入项目经验或项目状态流程。
- 改变可复用结论：新建或更新知识草稿，等待用户确认。
- 与当前 active knowledge 核心结论冲突：进入 Knowledge Conflict。
- 需要回到混沌记录或原始材料：`chaos_record`，把使用反馈追加到对应待铸卡或收件箱原件，不新造知识。

反馈不得直接覆盖 active knowledge，也不得因为一次成功或失败自动升级为规则。

## 混沌记录与目的绑定

- 讨论目的不清楚，或内容仍未定型时，先进入 `.orbitos/workflows/chaos-capture.md`，在 `01-收件箱/待铸卡/` 建立混沌记录；不强行分类，不产出正式知识。
- `purpose_status: unclear` 的记录只允许停留在不保存、保留原始或待铸卡，不得自动转成知识草稿或 active knowledge。
- 从混沌记录提炼知识草稿前，先按 `.orbitos/rules/core/knowledge-refinement.md` 的六个提炼门槛判断；不足时保留为待铸卡。

## 生命周期退出

每个知识候选、混沌记录或草稿都有明确出口，任何移动、归档或删除都保留用户确认门：

| 出口 | 含义 | 动作 |
|---|---|---|
| 不保存 | 本轮内容不进入 OrbitOS | 只记 event，不创建文件 |
| 保留原始不提炼 | 原样保留，不加工 | 无需额外动作 |
| 待铸卡 | 目的或条件不足，以后再处理 | 留在 `01-收件箱/待铸卡/` |
| 知识草稿 | 六个提炼门槛齐备 | 创建 `04-知识/00-草稿箱/` 草稿，等待用户确认 |
| 归档 | 不再活跃但保留历史 | 用户确认后移动 |
| 删除/清理 | 无价值或误记 | 用户确认后删除 |
| 过时/重复/被替代 | 被新内容取代 | 用户确认后标记 `superseded` 并指向替代者 |

目的不明（`purpose_status: unclear`）的内容只能停留在不保存、保留原始或待铸卡三个出口；退出动作由用户确认后执行。

不可逆出口（归档、删除、过时替代）要求 `confirmed_by: user`。记录 `knowledge_use` 时，`fit` 不是 `no_match` 必须保留 1—3 个 `sources`，`no_match` 必须保持空 `sources`。

## 最小闭环

```text
原始输入 -> 默认分流 -> 批量确认 -> 已入库 / 待铸卡(混沌) / 知识草稿 -> 用户确认 -> active knowledge
active knowledge -> 检索与适用性判断 -> 建议 / 行动 -> 结果反馈 -> event / 经验 / 草稿 / 混沌记录 / 冲突
退出出口：不保存 / 保留原始 / 待铸卡 / 草稿 / 归档 / 删除 / 过时替代
```

## 退出检查

- [ ] 已按默认分流优先级处理，未为低风险整理重复询问。
- [ ] 已按主题或来源形成批量确认，不把未确认内容移动或定稿。
- [ ] 目的不明的混沌记录未被强行分类或转成知识。
- [ ] 如调用知识，已记录来源、适用性判断和不适用边界。
- [ ] 如收到结果反馈，已记录 `knowledge_use`，并选择正确回写去向（含 `chaos_record`）。
- [ ] 退出动作（移动、归档、删除、过时替代）已取得用户确认。
- [ ] 未直接改写 active knowledge、规则或 Hindsight 主源。
- [ ] 已运行 validation。
