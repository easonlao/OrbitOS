# 对话目的与混沌记录

本 workflow 是"我还不清楚要把这段内容做成什么"的合法去处。它先把讨论目的、用户原话和未定型思考接住，不强行分类，也不产出正式知识。

## 触发条件

- 用户开始一段讨论，但目的还不清楚，或希望先记录上下文。
- 用户说"先记下来""我还不清楚""先放着""帮我留个底"。
- 用户希望保留讨论目的、自己的原话或未定型思考。
- Inbox Triage 或 Knowledge Flow 判定内容处于混沌状态，需要落到待铸卡。

## 混沌记录

混沌记录存放在 `01-收件箱/待铸卡/`，是与 OrbitOS 现有收件箱边界一致的原始层。它不是知识卡片，不进入 `04-知识/` 或 MAP。

使用模板 `.orbitos/templates/01-收件箱/待铸卡/00-混沌记录模板.md` 创建，frontmatter 只保留最小字段：

```yaml
---
title:
capture_kind: chaos
purpose_status: unclear
created:
updated:
tags:
---
```

- `capture_kind`：`chaos`（未定型内容）、`dialog_purpose`（主要是目的/上下文记录）、`mixed`（两者都有）。
- `purpose_status`：`clear`（目的清楚）、`unclear`（目的不清楚）、`pending`（已问用户一个最关键的问题，等待回答）。
- 正文按需保留 `## 讨论目的`、`## 用户原话`、`## 未定型思考` 区块；没有就省略，不补空块。

创建混沌记录是低风险捕获，不需要逐条确认；记录随时可以被保留、提炼或清理。

## 目的处理

- `purpose_status: unclear`：只允许停留在混沌/待铸层，不分类、不创建知识草稿、不产出正式知识。等用户能说清目的，改标为 `clear` 或 `pending` 后再进入对应流程。
- `purpose_status: clear`：按 Knowledge Flow 默认分流路由：项目材料、阅读候选，或 `knowledge_candidate`（进入知识提炼）。
- `purpose_status: pending`：已经向用户问了一个最关键的问题；等待回答期间保持现状。

## 混沌记录 -> 知识草稿

从混沌记录提炼知识草稿前，必须满足 `.orbitos/rules/core/knowledge-refinement.md` 的六个提炼门槛：核心判断、事实或真实依据、因果链、适用条件与边界、复用方式/首个行动、来源与不确定性。

满足门槛后进入 `knowledge-draft.md`，创建 `04-知识/00-草稿箱/` 草稿并等待用户确认。不满足时保留为待铸卡或原始材料，不强行生成草稿。

## 退出出口

混沌记录按以下出口收口。移动、归档或删除必须保持用户确认门，Agent 只提出去向和影响。

| 出口 | 含义 | 前置条件 |
|---|---|---|
| 不保存 | 本轮内容不进入 OrbitOS | 只记 event，不创建文件 |
| 保留原始不提炼 | 原样保留，不加工 | 无需额外动作 |
| 待铸卡 | 目的或条件不足，以后再处理 | 留在 `01-收件箱/待铸卡/` |
| 知识草稿 | 六个提炼门槛齐备 | 创建草稿并等待用户确认 |
| 归档 | 不再活跃但保留历史 | 用户确认后移动 |
| 删除/清理 | 无价值或误记 | 用户确认后删除 |
| 过时/重复/被替代 | 被新内容取代 | 用户确认后标记 `superseded` 并指向替代者 |

`purpose_status: unclear` 的内容只能停留在不保存、保留原始不提炼或待铸卡三个出口；不得自动转成知识草稿或 active knowledge。

不可逆出口（归档、删除/清理、过时/重复/被替代）落成混沌记录 frontmatter 时，必须携带 `confirmed_by: user`；只有 `user` 才代表用户确认，Agent 不得自证确认。

## 执行流程

1. 判断是否命中触发条件。
2. 用户已明确"不保存"：只写 event，不创建文件。
3. 否则按模板在 `01-收件箱/待铸卡/` 创建混沌记录，填写目的与现状。
4. 目的清楚且可复用：提出 `knowledge_candidate`，按提炼门槛判断是否进入知识草稿。
5. 目的不清楚：保持 `purpose_status: unclear`，不强行分类或产出知识。
6. 用户表达退出意图时，先展示去向和影响，等待确认后才执行移动、归档或删除。
7. 写 event 记录捕获与退出事实。
8. 执行 Validate Sync 与 Progress Sync。

## 执行清单

### 进入检查

- [ ] 已确认内容应进入混沌/待铸层，而不是其他明确去向。

### 执行检查

- [ ] 混沌记录位于 `01-收件箱/待铸卡/`，使用最小 frontmatter。
- [ ] `purpose_status: unclear` 的内容未被分类或转成知识。
- [ ] 提炼前已检查六个提炼门槛，不足时保留为待铸卡。
- [ ] 未在用户确认前移动、归档或删除混沌记录。

### 退出检查

- [ ] 已写 event。
- [ ] 已执行 Validate Sync 或 Progress Sync。

## 禁止

- 不把混沌记录写进 `04-知识/` 或 MAP。
- 不把目的不明的内容包装成知识草稿或 active knowledge。
- 不替用户确认移动、归档或删除。
- 不把对话全部自动持久化为知识；混沌状态和退出路径必须保留。
