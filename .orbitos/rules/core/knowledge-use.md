# Knowledge Use Rule

这条基础规则约束 Agent 如何把已确认知识用于当前判断。知识是有条件的依据，不是脱离场景的标准答案。

## 来源分层

- **已有知识**：来自完整读取的 active knowledge、适用的项目经验或明确引用的 Agent 经验。
- **当前事实**：来自用户本轮提供、当前文件、项目状态或工具验证的材料。
- **本次推断**：Agent 根据前两类来源形成的判断，不得伪装成过去经验。

Hindsight recall 只能提供候选线索；关键事实必须回查本地主源。

## 适用性检查

每张候选知识卡片至少检查：

1. 过去场景与当前场景的相同点。
2. 过去场景与当前场景的关键差异。
3. 卡片结论成立的条件是否存在。
4. 当前问题中哪些部分可以使用，哪些部分不能泛化。

关键词相同不足以证明经验适用。安全、法律、财务和不可逆后果优先于一般经验。

## 引用与行动边界

- 只引用完整读取过的卡片。
- 引用紧跟其支持的判断；末尾可再列本次实际引用。
- 没有直接适用知识时，明确写出“暂时没有找到能够直接套用的经验”。
- 涉及行动时，优先给出第一步、测试周期、首次投入上限、止损条件和放大条件。

## 不自动升级

- 知识调用事件不是新的知识卡片。
- 一次使用结果不直接覆盖 active knowledge。
- 需要改变可复用结论时，回到知识草稿并等待用户确认。
- 需要改变规则、ADR 或正式产物时，走对应确认路径。

## 反馈回写

- 反馈必须落到知识草稿、卡片或原始记录，而不是只停留在对话。
- `feedback_route: knowledge_draft`：把使用反馈追加到对应草稿并等待用户确认。
- `feedback_route: chaos_record`：把使用反馈追加到对应混沌记录或原始材料（`01-收件箱/待铸卡/`），不新造知识。
- 每个非 `none` 反馈去向都必须有 `feedback_ref`，并在 event 中记录 `knowledge_use` 事实。
