# Experience Record Rule

定义经验记录的边界与升级路径。核心原则：**经验只沉淀、不自动升级**。

## 记录边界

### 该记

- 验证过的可复用做法（做过一次、确认有效、后续还会用到）。
- 踩坑与返工（报错、误判、越界、返工原因）。
- 用户纠正（纠正了什么、为什么、以后怎么做）。
- 环境限制与绕行方案（某工具不可用、某路径有坑）。

### 不该记

- 单次任务的临时状态（当天数据、临时路径、搜索结果）——这些属于 event / 项目状态。
- 未经验证的猜测或尚未确认的方向。
- 隐私信息、账号凭证、未公开内容。
- 只对单个 agent 会话有意义、无跨会话复用价值的琐碎内容。

## 升级路径（显式，唯一入口）

经验文件本身**永远不升级**。一条经验要成为规则，必须：

1. 该经验已被**多次验证**或具有**明确普适性**。
2. 由 Agent 提出候选，写入待确认（如 issue / 收件箱），**用户明确确认**。
3. 用户确认后，才可写入 `core rules` 或产品文档（含 ADR）。

任何 agent 不得跳过用户确认，自行把经验提升为规则。这是 2026-06-15 用户"不重流程"要求与 2026-07-13 架构决定的延续（见 ADR-0008）。

## 隐私与安全

- 不记录账号、令牌、密钥、密码。
- 不记录未公开发布的敏感信息。
- 经验文件是 agent 本地记录，不属于 Product Repo 的公开内容；但发布或对外分享前仍须确认。

## 一致性

- 条目使用 `workflows/experience-capture.md` 规定的格式。
- 文件 frontmatter 的 `updated` 随追加同步更新。
- 经验文件只由对应 agent 自己维护；跨 agent 需要时，引用而非改写他人经验文件。
