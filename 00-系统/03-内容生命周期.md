# 内容生命周期

一份材料进入 OrbitOS 后，不会立刻被当成知识或正式成果。它会先保留原貌，再由你确认应该去哪里。

```text
收件箱 -> 默认分流 -> 批量确认 -> 确认后去向（项目 / 知识 / 素材 / 归档）-> 使用反馈回写
```

## 确认后去向：内容最终去哪里

批量确认后，内容按性质路由到对应位置：

- **项目内容**：写入对应项目目录 `03-项目/<项目>/`，具体子目录按该项目自己的 `AGENTS.md` 规定，不引入全局强制子目录结构。
- **知识类**：进入 `04-知识/`（先成草稿，你确认后才成为正式知识）。
- **素材 / 参考类**：进入 `06-资源/` 或 `99-归档/`。
- **长期回看或归档**：不再活跃但保留历史的，进入 `99-归档/`。

`07-输出` 已按设计消亡（2026-08-12），不再作为去向节点。

## 收件箱：先接住，不急着决定

文字、网址、图片、文件和临时想法都先放进 `01-收件箱/`。你可以让 Agent 盘点、归类和提出建议，但它不会未经确认移动或删除原件。

## 混沌记录：目的还不清楚的内容先待铸

当你还不确定一段内容要做什么，或讨论目的还没定型时，内容会先落在收件箱的待铸卡里，保留原话和未定型思考。它不会被强行分类或变成知识；等目的说清楚后，再决定去项目、去知识草稿还是退出。

## 退出出口

不再需要或已经过时的内容，从以下出口中选择，Agent 会先说明去向和影响再等你确认：

- 不保存：本轮内容不进入 OrbitOS。
- 保留原始不提炼：原样留着，不加工。
- 待铸卡：条件不足，以后再说。
- 归档：不再活跃但保留历史。
- 删除/清理：无价值或误记。
- 过时/重复/被替代：被新内容取代。

## 项目：需要持续推进的事情

当材料对应一个要持续做、需要跟进进展的目标时，它会关联到 `03-项目/`。你可以在那里看到当前状态、阻塞和下一步。

## 知识：已经确认、以后还能使用的结论

值得长期保留的理解，会先成为知识草稿。你确认后，它才成为正式知识；如果后来出现相反证据，系统会先请你处理冲突，而不会悄悄覆盖旧结论。

当 Agent 用这条知识帮助你做出判断后，你可以继续告诉它结果。结果只会按内容性质回写到事件、项目经验、Agent 经验或新的知识草稿；它不会直接覆盖原来的正式知识。

调用知识前，Agent 会先检查当前场景是否适用，并说明依据与边界。

## 阅读：和一份内容持续相处

书籍、长文或连续章节可以进入[[00-系统/模块/阅读|阅读模块]]。那里保留进度、批注和阅读洞察；洞察不会自动被当成正式知识。

## 归档：退出当前视野，不等于删除

结束或暂时不需要的内容可以归档，以后仍能回看。归档前会由你确认。
